# Données structurées JSON-LD

## Principe général

Le JSON-LD est injecté dans `<head>` via `useHead` sous la forme d'un graphe unique :

```json
{
  "@context": "https://schema.org",
  "@graph": [ ... nœuds ... ]
}
```

Un seul bloc `application/ld+json` par page, identifié par la clé `'schema-org-graph'`.
Nuxt/Unhead déduplique les injections sur la même clé.

---

## Nœuds produits par `buildJsonLd`

| Nœud             | Conditions de production                         |
| ---------------- | ------------------------------------------------ |
| `Organization`   | `appConfig.organization` présent                 |
| `WebSite`        | toujours                                         |
| `WebPage`        | `page` fourni et non null                        |
| `BreadcrumbList` | `buildBreadcrumbItems` retourne au moins un item |
| `ItemList`       | `accommodations` fourni et non vide              |
| `Accommodation`  | `accommodation` fourni et non null               |

---

## Convention `@id`

Chaque nœud est identifiable via un `@id` stable qui permet les liaisons entre nœuds :

| Nœud             | `@id`                          |
| ---------------- | ------------------------------ |
| `Organization`   | `{siteUrl}#organization`       |
| `WebSite`        | `{siteUrl}#website`            |
| `WebPage`        | `{canonicalUrl}#webpage`       |
| `BreadcrumbList` | `{canonicalUrl}#breadcrumb`    |
| `Accommodation`  | `{canonicalUrl}#accommodation` |

Les liaisons entre nœuds utilisent des références `{ "@id": "..." }` au lieu de dupliquer les données :

```json
"isPartOf": { "@id": "https://example.com#website" },
"mainEntity": { "@id": "https://example.com/bien#accommodation" }
```

---

## Liaisons critiques

**`WebPage` → `Accommodation`**

Quand une fiche bien est passée à `usePageSeo`, `WebPage.mainEntity` est automatiquement lié à `#accommodation`.
Cette liaison est gérée par le flag `hasAccommodation` dans `buildWebPageNode` :

```ts
if (hasAccommodation) {
  webPageNode.mainEntity = { '@id': `${canonicalUrl}#accommodation` }
}
```

**`WebPage` → `BreadcrumbList`**

Si le fil d'Ariane est présent, `WebPage.breadcrumb` est lié à `#breadcrumb`.

---

## Fil d'Ariane (`BreadcrumbList`)

`buildBreadcrumbItems` construit les entrées selon la nature de la page :

| Cas             | Entrées                              |
| --------------- | ------------------------------------ |
| Page éditoriale | Accueil → page                       |
| Fiche bien      | Accueil → listing → catégorie → bien |
| Liste de biens  | Accueil → listing → catégorie        |

Le fil d'Ariane n'est pas produit si aucun item n'est identifiable.

## Enrichir le graphe

Pour ajouter une propriété à un nœud existant, modifier uniquement `services/seo/schema.ts`.

Règles :

- Toute propriété ajoutée doit être alimentée par une donnée réelle (pas de fallback inventé).
- Si le contrat source ne fournit pas encore la donnée, durcir le schéma source avant d'enrichir.
- Ne pas introduire de logique métier dans `schema.ts` — uniquement du mapping.

---

## Enrichissements envisagés

Les pistes suivantes sont identifiées mais pas encore implémentées.
Chaque ajout doit être conditionné à l'existence d'une donnée réelle et fiable côté contenu.

**`Organization`**

- `sameAs` — profils sociaux et annuaires de référence
- `contactPoint` — point de contact structuré
- `areaServed` — zone géographique couverte
- `address` — adresse structurée en `PostalAddress`

**`WebSite`**

- `potentialAction` de recherche si le produit expose une recherche publique

**`Accommodation`**

- `amenityFeature` — équipements sous forme de `LocationFeatureSpecification`
- `occupancy` — capacité d'accueil
- `yearBuilt` — année de construction
- sous-type précis (`Apartment`, `House`) si le métier permet de distinguer les catégories

**`Offer`**

- `availability` — disponibilité (`InStock` / `OutOfStock`)
- `seller` — lien vers `Organization`
- `url` — URL directe de l'offre
- `priceValidUntil` — date d'expiration du prix si disponible

**`ItemList`**

- `name` — nom de la liste
- `description` — description de la sélection
- `url` — URL de la page de liste

**`WebPage`**

- évaluer `Article` pour les pages éditoriales à contenu long ou informationnel
  (conditionne aussi `ogType` dans `useSeoMeta`)

# Sitemap et multilingue

## Sitemap XML

Le sitemap est géré par `@nuxtjs/sitemap` (configuré dans `nuxt.config.ts`).

```ts
sitemap: {
  siteUrl,
  autoLastmod: true,
  gzip: true,
  includeAppSources: true,
  sources: ['/api/__sitemap__/urls'],
}
```

- `includeAppSources: true` — découvre automatiquement les routes statiques depuis `app/pages/`.
- `sources` — injecte les URLs dynamiques (biens, pages éditoriales) via une route serveur dédiée.

---

## Source dynamique : `server/api/__sitemap__/urls.get.ts`

Ce handler produit les entrées dynamiques du sitemap en agrégeant les données de contenu.

Structure d'une entrée :

```ts
{
  loc: '/fr/bien-slug',
  lastmod: '2025-01-15',
  changefreq: 'weekly',
  priority: 0.8,
}
```

Priorités appliquées :

| Type              | `priority` | `changefreq` |
| ----------------- | ---------- | ------------ |
| Page d'accueil    | `1`        | `monthly`    |
| Page éditoriale   | `0.7`      | `monthly`    |
| Fiche bien active | `0.8`      | `weekly`     |

Les biens avec `isActive === false` sont exclus du sitemap.

## Multilingue : liens `hreflang`

`buildAlternateLinks` dans `usePageSeo` génère les balises `<link rel="alternate">` pour chaque locale déclarée dans `AVAILABLES_LOCALES`.

```html
<link rel="alternate" hreflang="fr" href="https://example.com/fr/page" />
<link rel="alternate" hreflang="en" href="https://example.com/en/page" />
<link rel="alternate" hreflang="es" href="https://example.com/es/page" />
<link rel="alternate" hreflang="x-default" href="https://example.com/fr/page" />
```

- `x-default` pointe vers le locale de fallback (`FALLBACK_LOCALE`).
- Si `switchLocalePath` ne retourne pas de chemin pour un locale donné, la balise est omise.
- Les liens `alternate` sont injectés via `useHead`, pas via `useSeoMeta`.

## Stratégie i18n et routing

`strategy: 'prefix'` — toutes les routes sont préfixées par le code locale (`/fr/`, `/en/`, `/es/`).

Certaines routes ont des chemins localisés explicites, déclarés dans `nuxt.config.ts` :

```ts
pages: {
  'properties/[realEstateListing]/index': {
    fr: '/biens/[realEstateListing]',
    en: '/properties/[realEstateListing]',
    es: '/propiedades/[realEstateListing]',
  },
}
```

Les routes non déclarées utilisent le nom de fichier comme segment de chemin, préfixé par le locale.

## `robots.txt`

Le fichier `robots.txt` doit être servi via une route serveur (`server/routes/robots.txt.ts`)
pour permettre des règles conditionnelles selon l'environnement.

Convention attendue :

- En production indexable : `Allow: /` + pointeur vers le sitemap.
- Hors production : `Disallow: /` pour bloquer tout crawl.

La meta `robots` par page contrôle l'indexation au niveau page ;
`robots.txt` contrôle l'accès au niveau crawl — les deux doivent être cohérents.

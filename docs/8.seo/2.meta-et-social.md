# Métadonnées et balises sociales

## Champs gérés par `buildSeoMeta`

| Champ | Source | Notes |
|---|---|---|
| `title` | `page.metaTitle` | |
| `description` | `page.metaDescription` | |
| `canonicalUrl` | `siteUrl` + `route.path` | toujours absolue |
| `robots` | `isIndexable` | `index, follow` ou `noindex, nofollow` |
| `ogTitle` | `page.metaTitle` | |
| `ogDescription` | `page.metaDescription` | |
| `ogUrl` | `siteUrl` + `route.path` | |
| `ogType` | fixé à `'website'` | voir note ci-dessous |
| `ogImage` | `page.image[0].url` | absolue via `toAbsoluteUrl` |
| `twitterCard` | `'summary_large_image'` si image, sinon `'summary'` | |

| `twitterImage` | `page.image[0].url` | |
| `articlePublishedTime` | `page.datePublished` | |
| `articleModifiedTime` | `page.dateModified` | |

## Indexation

`isIndexable` est calculé dans `usePageSeo` :

```ts
const isIndexable = computed(() => config.public.isIndexable === true)
```

`config.public.isIndexable` vaut `true` uniquement si `APP_ENV === 'prod'` **et** `NODE_ENV === 'production'`.
En mode `nuxt dev`, l'indexation est toujours désactivée même si `APP_ENV=prod`.

Le champ `robots` injecté dans `useSeoMeta` prend alors `'noindex, nofollow'`.

---

## URL canonique

Toutes les URLs canoniques sont construites par `toAbsoluteUrl(siteUrl, path)`.
`siteUrl` vient de `SITE_URL` (variable d'environnement) ou `http://localhost:3000` en développement.

L'URL canonique est aussi injectée dans `useHead` via :

```ts
{ rel: 'canonical', href: seoMeta.value.canonicalUrl }
```

Si `canonicalUrl` est absent (page sans métadonnées), la balise `canonical` n'est pas émise.

---

## Note : `ogType` et dates d'article

`ogType` est actuellement fixé à `'website'` pour toutes les pages.
Les champs `articlePublishedTime` et `articleModifiedTime` ne sont interprétés par les plateformes sociales que si `ogType === 'article'`.

Pour les pages éditoriales à contenu long, il faudra dériver `ogType` depuis le type de page
(aligné avec l'évaluation de `Article` vs `WebPage` prévue dans la spec 024).

---

## `ogSiteName`

`ogSiteName` est le seul champ non réactif : il est passé directement depuis `config.public.siteName`
car le nom du site ne change pas entre les pages.

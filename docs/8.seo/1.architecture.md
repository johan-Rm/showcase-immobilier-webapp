# Architecture SEO

## Rôle de chaque couche

| Couche | Fichier | Responsabilité |
|---|---|---|
| Entry point | `app/pages/*.vue` | Fournit les données réactives à `usePageSeo()` |
| Orchestrateur | `app/composables/usePageSeo.ts` | Lit le contexte Nuxt, applique `useSeoMeta` et `useHead` |
| Projection pure | `services/seo/schema.ts` | Transforme les données métier en structures SEO sérialisables |

La logique de transformation ne doit jamais remonter dans le composable.
Le composable ne doit jamais contenir de logique métier ou de mapping de données.

---

## Flux de données

```
page (ComputedRef<WebPage>)
  └─► usePageSeo()
        ├─► buildSeoMeta()   → seoMeta (ComputedRef)
        │     └─► useSeoMeta(title, description, ogTitle, ...)
        ├─► buildJsonLd()    → jsonLd (ComputedRef)
        │     └─► useHead({ script: [{ type: 'application/ld+json' }] })
        └─► buildAlternateLinks()
              └─► useHead({ link: [{ rel: 'alternate', hreflang }] })
```

---

## Contrat d'appel

`usePageSeo` accepte trois arguments optionnels, tous en `ComputedRef` :

```ts
usePageSeo(
  page?,           // ComputedRef<WebPage | null>
  accommodations?, // ComputedRef<Accommodation[] | null>
  accommodation?,  // ComputedRef<Accommodation | null>
)
```

- Passer uniquement les données réellement disponibles sur la page.
- Ne jamais passer de valeurs brutes non réactives — le composable s'attend à des `ComputedRef`.
- L'entry point reste responsable de fournir uniquement ce qui doit être exposé en JSON-LD.

---

## Ajouter le SEO sur une nouvelle page

```ts
// app/pages/ma-page.vue — section 11. Metadonnees ecran ou page
const page = computed(() => getPageBySlug('ma-page'))

usePageSeo(page)
```

Pour une page avec une liste de biens :

```ts
const page = computed(() => getPageBySlug('properties'))
const accommodations = computed(() => store.activeAccommodations)

usePageSeo(page, accommodations)
```

Pour une fiche bien :

```ts
const page = computed(() => getPageBySlug(route.path))
const accommodation = computed(() => store.currentAccommodation)

usePageSeo(page, undefined, accommodation)
```

---

## Valeurs retournées

`usePageSeo` retourne `{ seoMeta, jsonLd }` — deux `ComputedRef` exposés pour le debug ou la réutilisation.
Ces valeurs ne sont pas nécessaires au fonctionnement normal : les effets de bord (`useSeoMeta`, `useHead`) sont déjà branchés à l'appel.

---

## Séparation avec `services/seo/schema.ts`

`buildSeoMeta` et `buildJsonLd` sont des fonctions pures : elles prennent des données normalisées et retournent des structures sérialisables.
Elles n'accèdent pas à la route, au runtime config ni à aucun composable Nuxt.
Ce sont les seuls points d'extension légitimes pour enrichir le SEO.

Voir [3. Données structurées](3.donnees-structurees.md) pour le détail des nœuds Schema.org.

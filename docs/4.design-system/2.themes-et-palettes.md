# Thèmes et palettes

- Role: décrire la source de vérité des thèmes, les palettes de couleurs et la pipeline YAML → CSS.
- Related: [1.tailwind-et-tokens.md](./1.tailwind-et-tokens.md), [3.color-mode.md](./3.color-mode.md)

## Source de vérité

[themes.yaml](../../themes.yaml) est l'unique source de vérité pour les couleurs et polices du projet.
Il définit deux niveaux : les palettes de couleurs et les thèmes.

```
themes.yaml
├── themes.colors     → palettes nommées avec toutes leurs teintes (50–950)
├── themes.light      → mapping de tokens sémantiques vers les palettes
├── themes.dark       → mapping de tokens sémantiques vers les palettes
└── themes.kasbah     → mapping de tokens sémantiques vers les palettes
```

Toute modification de couleur ou de police doit passer par ce fichier.

## Pipeline YAML → CSS

Les thèmes ne sont pas compilés au build : ils sont exposés dynamiquement par deux routes serveur Nitro.

```
themes.yaml
  └─► GET /themes.json   → JSON structuré (palettes + thèmes résolus)
  └─► GET /themes.css    → CSS avec variables custom par sélecteur
```

### /themes.css

[server/routes/themes.css.ts](../../server/routes/themes.css.ts) génère le CSS injecté dans la page.

**Conversion HEX → RGB :**

```ts
const hexToRgb = (hex: string) => {
  // '#ceb182' → '206 177 130'
}
```

Les valeurs sont au format `r g b` sans `rgb()` pour permettre l'usage avec alpha-value en Tailwind.

**Sélecteurs générés :**

| Thème | Sélecteur CSS |
|---|---|
| `light` | `:root` |
| `dark` | `.dark` |
| `kasbah` | `.theme-kasbah` |

Tout thème dont la clé n'est ni `light` ni `dark` reçoit le sélecteur `.theme-{clé}`.

**Exemple de sortie :**

```css
:root {
  --font-heading: 'Inter', system-ui, -apple-system, sans-serif;
  --font-body: 'Inter', system-ui, -apple-system, sans-serif;
  --color-bg: 206 177 130;
  --color-surface: 248 237 214;
  --color-primary: 16 32 59;
  --color-foreground: 16 32 59;
  --color-border: 248 237 214;
  --color-ring: 16 32 59;
  /* + toutes les teintes de chaque palette mappée (primary-50 … primary-950, etc.) */
}

.dark {
  --color-bg: 7 15 22;
  --color-primary: 223 198 137;
  /* ... */
}

.theme-kasbah {
  --color-bg: 67 139 171;
  --color-primary: 248 237 214;
  /* ... */
}
```

### Règles de fallback dans le CSS généré

Lorsqu'un token n'est pas défini dans le YAML, le serveur applique ces fallbacks :

```
border  ← surface ← background
ring    ← primary
primary-foreground ← background ← '#ffffff'
secondary-foreground ← foreground ← '#000000'
```

### /themes.json

[server/routes/themes.json.ts](../../server/routes/themes.json.ts) expose le même contenu sous forme JSON.
Utilisé par [DesignSystem.vue](../../app/components/udrawer/DesignSystem.vue) pour afficher la palette active en interface.

## Chargement dans l'application

Le CSS des thèmes est chargé dans [app/app.vue](../../app/app.vue) via un lien `<link>` pointant sur `/themes.css`.
La route est mise en cache par SWR en production.

En développement, tout changement dans `themes.yaml` est pris en compte au rechargement de la page. En production, une invalidation de cache est nécessaire si les thèmes changent.

## Ajouter un thème

1. Déclarer les palettes nécessaires dans `themes.yaml > themes.colors` si elles n'existent pas.
2. Ajouter une entrée dans `themes.yaml` avec la clé souhaitée (ex. `desert`).
3. Mapper les tokens sémantiques requis (`primary`, `background`, `surface`, `foreground`, `heading`, `overlay`, `transition`).
4. Ajouter la valeur dans `ThemeMode` dans [shared/types/ui.ts](../../shared/types/ui.ts).
5. Mettre à jour `useDesignSystem` pour gérer le comportement colorMode associé.

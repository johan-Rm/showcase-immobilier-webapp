# Color mode et useDesignSystem

- Role: décrire la gestion du thème actif, du color mode et des effets cinéma à l'exécution.
- Related: [1.tailwind-et-tokens.md](./1.tailwind-et-tokens.md), [2.themes-et-palettes.md](./2.themes-et-palettes.md)

## Module color mode

Le color mode est fourni par `@nuxt/ui` (v4.7.1+), qui embarque `@nuxtjs/color-mode`.
Il n'y a pas de dépendance séparée à installer.

Configuration dans [nuxt.config.ts](../../nuxt.config.ts) :

```ts
colorMode: {
  preference: 'light',
  fallback: 'light',
},
ui: {
  colorMode: true,
},
```

`useColorMode()` est auto-importé dans tout le projet via `@nuxt/ui`.

---

## Types

Définis dans [shared/types/ui.ts](../../shared/types/ui.ts) :

```ts
export type ThemeMode = 'light' | 'dark' | 'kasbah'
export type CinemaMode = 'soft' | 'strong' | 'none'
export type TransitionMode = 'fade' | 'flash' | 'slide' | 'zoomCut' | 'crossZoom'
```

`ThemeMode` contrôle le thème visuel global.
`CinemaMode` contrôle l'intensité du calque de contraste sur les images plein écran.
`TransitionMode` contrôle l'animation de transition entre les screens.

## Composable useDesignSystem

[app/composables/useDesignSystem.ts](../../app/composables/useDesignSystem.ts) est le point d'entrée unique pour la gestion du thème et du mode cinéma. Il est instancié une seule fois via `createSharedComposable`.

### API exposée

```ts
const {
  themeMode,         // Ref<ThemeMode> — thème actif
  setTheme,          // (next: ThemeMode) => void
  cinemaMode,        // Ref<CinemaMode> — intensité du calque cinéma
  setCinema,         // (next: CinemaMode) => void
  cinemaOverlayClass // ComputedRef<string> — classe Tailwind du calque
} = useDesignSystem()
```

### État partagé

L'état est stocké dans des `useState` Nuxt nommés pour être partagé entre toutes les instances :

```ts
const themeMode  = useState<ThemeMode>('ui.theme.mode',  () => 'light')
const cinemaMode = useState<CinemaMode>('ui.cinema.mode', () => 'strong')
```

## Flux de changement de thème

```
setTheme(next)
  └─► themeMode.value = next
        ├─► watch → colorMode.preference = next       (pour 'light' / 'dark')
        │          colorMode.preference = 'dark'       (pour 'kasbah')
        └─► useHead → htmlAttrs.class.theme-kasbah     (true si 'kasbah', sinon false)
              └─► CSS :root / .dark / .theme-kasbah prend effet
                    └─► variables --color-* changent globalement
```

Le thème `kasbah` force `colorMode.preference = 'dark'`, ce qui active simultanément la classe `.dark` (gérée par `@nuxt/ui`) et la classe `.theme-kasbah` (gérée par `useHead`).
Les deux sélecteurs CSS coexistent : `.theme-kasbah` écrase `.dark` sur les variables qui diffèrent.

---

## Classe HTML appliquée

`useDesignSystem` injecte la classe `theme-kasbah` sur `<html>` via `useHead` :

```ts
useHead({
  htmlAttrs: {
    class: computed(() => ({
      'theme-kasbah': themeMode.value === 'kasbah',
    })),
  },
})
```

Pour les thèmes `light` et `dark`, c'est `@nuxt/ui` qui gère la classe `.dark` sur `<html>` via `colorMode.preference`.

## Mode cinéma

`cinemaMode` contrôle un calque de gradient radial appliqué sur les images de fond plein écran.

```ts
const cinemaOverlayClass = computed(() => {
  if (cinemaMode.value === 'strong') {
    return 'bg-[radial-gradient(circle_at_30%_40%,...)]'
  }
  if (cinemaMode.value === 'soft') {
    return 'bg-[radial-gradient(circle_at_30%_40%,...)]'
  }
  return 'hidden'
})
```

| Valeur | Effet |
|---|---|
| `strong` | Gradient marqué — accentue le contraste texte/image |
| `soft` | Gradient léger — atténue sans dominer l'image |
| `none` | Classe `hidden` — calque invisible |

La valeur par défaut est `strong`.

## Invariants

- `useDesignSystem` est le seul endroit qui écrit dans `colorMode.preference` — ne pas appeler `useColorMode()` directement pour changer le thème.
- Ne pas modifier `themeMode` directement depuis un composant — toujours passer par `setTheme()`.
- Le thème kasbah force `.dark` sur `colorMode` : ne pas supposer que `.dark` implique le thème dark natif.
- `createSharedComposable` garantit une seule instance — ne pas instancier plusieurs fois pour éviter des watchers dupliqués.

# Tailwind CSS et tokens de design

- Role: décrire la configuration Tailwind, le pattern token-based RGB et les tokens sémantiques du projet.
- Related: [2.themes-et-palettes.md](./2.themes-et-palettes.md), [3.color-mode.md](./3.color-mode.md)

## Configuration Tailwind

Le fichier [tailwind.config.ts](../../tailwind.config.ts) active le dark mode par classe HTML et étend le thème avec des tokens sémantiques résolus via variables CSS.

```ts
// tailwind.config.ts
darkMode: 'class'
```

Le contenu scanné par Tailwind est limité aux fichiers du dossier `app/` :

```ts
content: [
  './app/components/**/*.{vue,js,ts}',
  './app/layouts/**/*.{vue,js,ts}',
  './app/pages/**/*.{vue,js,ts}',
  './app/app.vue',
]
```

## Pattern token-based RGB

Toutes les couleurs Tailwind du projet sont définies via des variables CSS au format RGB (sans `rgb()`, sans `#`), ce qui permet l'usage de la valeur alpha dans les utilitaires Tailwind.

```ts
const color = (name: string) => `rgb(var(--color-${name}) / <alpha-value>)`
```

**Exemple d'usage en template :**

```html
<div class="bg-primary/80 text-foreground">...</div>
```

```html
<!-- Equivalent inline -->
<div style="background: rgb(var(--color-primary) / 0.8)">...</div>
```

Les variables CSS sont générées dynamiquement par `/themes.css` au démarrage, selon le thème actif. Voir [2.themes-et-palettes.md](./2.themes-et-palettes.md).

## Tokens sémantiques

Les tokens sont définis dans `tailwind.config.ts > theme.extend.colors`. Chaque token dispose d'une valeur `DEFAULT` et d'une échelle de teintes (50–950).

| Token                  | Variable CSS                   | Description                         |
| ---------------------- | ------------------------------ | ----------------------------------- |
| `primary`              | `--color-primary`              | Accent principal, boutons CTA       |
| `primary-foreground`   | `--color-primary-foreground`   | Texte sur fond primary              |
| `secondary`            | `--color-secondary`            | Accent secondaire                   |
| `secondary-foreground` | `--color-secondary-foreground` | Texte sur fond secondary            |
| `background`           | `--color-bg`                   | Fond principal de l'interface       |
| `foreground`           | `--color-foreground`           | Texte courant                       |
| `surface`              | `--color-surface`              | Surfaces élevées (cartes, panneaux) |
| `heading`              | `--color-heading`              | Couleur des titres                  |
| `border`               | `--color-border`               | Contours et séparations             |
| `ring`                 | `--color-ring`                 | Focus et états actifs               |
| `overlay`              | `--color-overlay`              | Calques d'assombrissement           |

Chaque token avec échelle expose les classes Tailwind `primary-50` à `primary-950`.

## Tokens de police

Les familles de police sont résolvées via variables CSS, avec fallback sur les polices système :

```ts
fontFamily: {
  heading: ['var(--font-heading)', ...defaultTheme.fontFamily.sans],
  body:    ['var(--font-body)',    ...defaultTheme.fontFamily.sans],
}
```

Les valeurs de `--font-heading` et `--font-body` sont injectées par `/themes.css` selon le thème actif.
Le projet utilise Inter (auto-hébergé via `@font-face` dans [theme.css](../../app/assets/styles/theme.css)).

## Utilitaires raccourcis

Deux groupes d'utilitaires raccourcis sont définis pour les usages les plus fréquents :

```ts
backgroundColor: {
  skin: {
    surface: color('surface'),
    base:    color('bg'),
  },
},
textColor: {
  skin: {
    base: color('foreground'),
  },
},
```

Usage : `bg-skin-surface`, `bg-skin-base`, `text-skin-base`.

## Entry CSS

Le fichier [app/assets/main.css](../../app/assets/main.css) est le point d'entrée CSS du projet. Il charge la config Tailwind, les styles de base et le framework UI dans l'ordre suivant :

```css
@config '../../tailwind.config.ts';
@import './styles/theme.css';
@import './styles/markdown.css';
@import 'tailwindcss';
@import '@nuxt/ui';

@theme {
  --text-tiny: 0.525rem;
}
```

L'import de `tailwindcss` après `theme.css` garantit que les variables CSS de base sont déclarées avant la génération des utilitaires.

## Invariants

- Ne pas utiliser les classes `dark:` Tailwind — le projet repose exclusivement sur des variables CSS pilotées par les sélecteurs `:root`, `.dark` et `.theme-kasbah`.
- Ne pas définir de couleurs en dur (`#hex`, `rgb(...)`) dans les templates — toujours passer par un token sémantique.
- Ne pas étendre `tailwind.config.ts` avec des couleurs statiques — les nouvelles couleurs passent par `themes.yaml`.

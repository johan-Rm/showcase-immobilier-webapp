## Structure des routes

```text
app/pages/
├── index.vue                                          /
├── contact.vue                                        /contact
├── echo.vue                                           /echo
├── [...page].vue                                      /:page  (catch-all éditorial)
└── properties/
    └── [realEstateListing]/
        ├── index.vue                                  /properties/:realEstateListing
        └── [accommodationCategory]/
            ├── index.vue                              /properties/:realEstateListing/:accommodationCategory
            └── [accommodationSlug].vue                /properties/:realEstateListing/:accommodationCategory/:accommodationSlug
```

Toutes ces routes fonctionnent sous un préfixe de locale injecté par le middleware
`locale.global.ts`. Les URLs réelles sont de la forme `/fr/contact`, `/en/properties/...`.

## Préfixe de locale

Le projet utilise un préfixe de locale dans toutes les URLs (`/fr/`, `/en/`, `/es/`).

Le middleware `locale.global.ts` garantit cette normalisation :

- si une URL ne porte pas de préfixe de locale valide, il redirige vers la version localisée
- il lit la locale courante via `useLang().localeSetting` avec fallback sur `FALLBACK_LOCALE`
- les chemins `/api/*` sont exemptés de ce traitement

```ts
// /contact → /fr/contact
return navigateTo({
  path: `/${locale}${to.path === '/' ? '' : to.path}`,
  query: to.query,
  hash: to.hash,
})
```

Règle : ne jamais construire une URL hardcodée sans préfixe de locale. Utiliser les
helpers de navigation i18n ou `useLang()` pour résoudre la locale courante.

## Route catch-all éditoriale

La page `[...page].vue` absorbe toutes les routes éditoriales dynamiques (`/fr/home`,
`/fr/investir-a-essaouira`, etc.).

Elle est protégée par un `validate` dans `definePageMeta` pour rejeter les URL ambiguës
avant le rendu :

```ts
definePageMeta({
  validate: (route) => {
    const param = route.params.page
    if (Array.isArray(param)) {
      return param.length === 1 && pattern.test(param[0] ?? '')
    }
    return typeof param === 'string' && pattern.test(param)
  },
})
```

Le pattern accepte uniquement les slugs `kebab-case` simples (pas de segments profonds).
Un slug invalide produit une 404 propre avant d'atteindre le composant.

## Hiérarchie des routes immobilières

La structure `properties/[realEstateListing]/[accommodationCategory]/[accommodationSlug]`
reflète directement le modèle de données :

| Segment   | Paramètre               | Exemple                               |
| --------- | ----------------------- | ------------------------------------- |
| Listing   | `realEstateListing`     | `bien-a-vendre`                       |
| Catégorie | `accommodationCategory` | `riad`                                |
| Bien      | `accommodationSlug`     | `riad-boutique-renove-medina-bavr001` |

Les pages intermédiaires (`index.vue`) permettent une navigation par niveau sans
charger immédiatement la fiche complète.

## Middlewares globaux

Les fichiers suffixés `.global.ts` dans `app/middleware/` s'exécutent à chaque
navigation, dans l'ordre alphabétique.

### `locale.global.ts`

- Exécuté côté serveur et client.
- Garantit qu'une locale valide préfixe chaque URL.
- Ne doit pas utiliser `useRoute()` — utilise uniquement `to` et `from`.

### `construction-lock.global.ts`

- Exécuté côté client uniquement (`import.meta.server` guard en tête).
- Bloque la navigation et ouvre la modal de construction si le mode est actif.
- Ignore la navigation initiale (`!from.matched.length`) pour ne pas bloquer l'hydratation.
- Ignore les navigations identiques (`to.fullPath === from.fullPath`).

```ts
export default defineNuxtRouteMiddleware((to, from) => {
  if (import.meta.server) return // SSR guard
  if (!from.matched.length) return // hydratation initiale
  if (to.fullPath === from.fullPath) return // no-op
  // ...
})
```

## Scroll behavior

Le scroll automatique du router est désactivé dans `router.options.ts` :

```ts
export default <RouterConfig>{
  scrollBehavior() {
    return false
  },
}
```

Le scroll entre pages est entièrement géré par `useScreenSystem`, qui pilote les
transitions visuelles entre écrans. Laisser Vue Router gérer le scroll provoquerait
des conflits avec ce système.

## `definePageMeta`

Utilisé dans les pages pour déclarer :

- `validate` — validation de paramètre de route avant rendu (exemple : catch-all)
- `layout` — layout spécifique si différent du défaut
- `middleware` — middleware nommé à appliquer sur la route uniquement

```ts
definePageMeta({
  layout: 'full-screen',
  middleware: ['auth'],
  validate: (route) => Boolean(route.params.slug),
})
```

Emplacement : en fin de `<script setup>`, dans le bloc `// 11. Métadonnées écran ou page`
du standard script setup.

## Navigation programmatique

| Besoin                             | API à utiliser                        |
| ---------------------------------- | ------------------------------------- |
| Rediriger vers une URL             | `navigateTo('/fr/contact')`           |
| Rediriger en préservant query/hash | `navigateTo({ path, query, hash })`   |
| Bloquer la navigation              | `return abortNavigation()`            |
| Naviguer vers une route externe    | `navigateTo(url, { external: true })` |

Ne pas utiliser `useRouter().push()` depuis un middleware — uniquement `navigateTo`.

## Règles

- les middlewares n'appellent pas `useRoute()` : accéder aux paramètres via `to` et `from`
- les middlewares restent légers : pas d'I/O bloquant, pas d'appel réseau
- tout guard client-only commence par `if (import.meta.server) return`
- la navigation initiale (`!from.matched.length`) est toujours laissée passer
- les URLs construites programmatiquement incluent le préfixe de locale

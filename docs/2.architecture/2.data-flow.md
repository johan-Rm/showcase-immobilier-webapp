# Data Flow

- Role: expliciter le flux principal des donnees dans l application.
- Related: [./1.application-architecture.md](./1.application-architecture.md)

## Main Flow

1. `app/app.vue` initialise le contexte global a partir de la locale courante
2. `useNuxtServerInit` charge metadata puis donnees principales
3. `services/content/loaders.ts` lit les fichiers `content/*` via des chargeurs localises
4. les stores stockent les ressources brutes et deleguent les enrichissements aux mappers
5. les composables exposent une API reactive de lookup et d orchestration a l UI
6. les pages resolvent les screens a afficher et les composants rendent les donnees preparees

## Editorial Screen Flow

1. la route resolve une page editoriale via `useWebPage`
2. la page recherche les blocs `hasPart` utiles par `slug` ou `identifier`
3. `useScreenSystem` calcule l ecran actif, pilote les transitions et synchronise l ecran actif avec le hash URL
4. chaque screen recupere un bloc deja normalise et l affiche

## Rules

- un composant n appelle jamais l API (ni interne, ni externe) : les appels reseau vivent dans les composables ou les pages
- l API externe passe par `services/` ou la couche serveur (BFF), jamais en direct depuis un composant
- un store n absorbe pas la logique metier pure
- un service ne depend pas du framework UI
- le sens du flux doit rester lisible et testable
- le changement de locale invalide et recharge les donnees core de facon explicite
- les pages n ont pas a reparser Markdown, frontmatter ou YAML

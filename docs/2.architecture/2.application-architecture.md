# Application Architecture

- Role: decrire les couches applicatives et leurs responsabilites.
- Related: [./3.data-flow.md](./3.data-flow.md), [../3.application/1.index.md](../3.application/1.index.md)

## Overview

Le projet repose sur une separation claire entre orchestration UI, etat global, logique metier et couche serveur.

Le runtime reel s articule autour de trois blocs dominants :

1. un bootstrap global non bloquant dans `app/app.vue` qui lance `initCoreData()` apres hydratation
2. une pipeline de chargement de contenu dans `services/content/loaders.ts`
3. des pages Nuxt qui orchestrent des screens plein viewport a partir de contrats normalises

Les repertoires structurants sont :

- `app/` : pages, layouts, composants, composables, stores et plugins Nuxt
- `services/` : logique metier pure, transformations et acces externes
- `server/` : routes et traitements serveur Nitro
- `schemas/` : contrats et artefacts de types
- `shared/` : utilitaires et contrats partageables

## Core Layers

### Pages

Les pages orchestrent les routes et la composition globale d une experience.
Elles declarent le contexte de route, la meta, les layouts et les ecrans a afficher.
Sur ce projet, elles pilotent aussi la navigation par screens (`data-screen`, ancres, transitions, orientation x ou y).

### Components

Les composants portent l affichage et la composition visuelle.
Ils doivent rester centres sur la presentation et ne pas absorber la logique metier.

### Composables

Les composables servent de passerelle entre l interface et la logique applicative.
Ils exposent une API reactive adaptee a l UI.
Ils portent aussi l orchestration transverse du projet : bootstrap initial, navigation de screens, synchronisation des ancres, metadata et locale.

### Stores

Les stores centralisent l etat global et l orchestration metier partagee.
Ils pilotent le chargement, le cache et la synchronisation de donnees cote front.
Dans l etat actuel du repo, `webPage`, `metadata` et `accommodation` servent de caches reactifs des donnees chargees depuis `content/`.

### Services

Les services portent la logique metier pure, les transformations, les acces externes et le parsing.
Ils ne doivent pas dependre de Vue, Nuxt ou Pinia.
Ici, ils couvrent notamment :

- les loaders de contenu Markdown et YAML
- les mappers DTO -> contrats applicatifs
- le hook de generation des artefacts de schemas au build

### Server

La couche serveur expose les routes et traitements Nitro.
Elle gere les contrats HTTP, la validation et les integrations cote serveur.
Le perimetre observe reste volontairement reduit : endpoints de demo, exposition des themes et echo API.

## Observed Runtime Flow

### Bootstrap applicatif

- `app/app.vue` affiche le shell initial puis lance `useNuxtServerInit().initCoreData()` apres hydratation
- `useNuxtServerInit` charge d abord les metadata, puis les donnees principales (`web pages`, `accommodations`)
- un changement de locale relance explicitement ce bootstrap

### Pipeline de contenu

- `services/content/loaders.ts` charge les fichiers `content/*` via `import.meta.glob`
- le service parse le frontmatter Markdown et les ressources YAML
- les stores stockent les donnees brutes ou DTO
- les getters de store deleguent l enrichissement aux mappers `@services/mapper/*`
- les composables exposent ensuite des helpers reactifs de lookup a l UI

### Navigation editoriale

- les routes principales assemblent des `UPageSection` adresses via `data-screen`
- `useScreenSystem` gere clavier, wheel, swipe et transition
- `useScreenAnchors` synchronise hash URL et ecran actif
- certains screens sont resolves dynamiquement a partir du contenu editorial (`WebPage.hasPart`) et de la query string

## Structural Invariants

- `pages/` orchestre ; `components/` affiche
- un composable n appelle pas directement une API si un service est la bonne couche
- un service reste framework-agnostic
- la logique metier ne remonte pas dans les composants d affichage
- les contrats et transformations non triviales doivent rester testables
- le bootstrap global reste dans `app.vue` et `useNuxtServerInit`, pas dans les pages
- le chargement de contenu localise passe par `services/content/loaders.ts`
- les pages editoriales consomment un contrat normalise (`WebPage`, `CreativeWork`) au lieu de reparsing le contenu dans le template

# Page, Layout, Screen Model

- Role: formaliser le modele de composition principal des routes du projet.
- Related: [../../app/pages/README.md](../../app/pages/README.md)

## Hierarchy

```text
PAGE
  -> LAYOUT
    -> SCREEN
      -> COMPONENT
        -> UI ELEMENT
```

## Definitions

### Page

Une page est un point d entree de route.
Elle assemble un ou plusieurs screens et orchestre l experience de la route.

### Layout

Le layout fournit le cadre persistant : header, footer, navigation, overlays et conteneur principal.

### Screen

Un screen est une unite d intention.
Il structure une section de l experience avec un objectif clair, une composition interne et un cycle de vie visuel.

### Component

Le composant implemente le rendu d un screen ou d un fragment de screen.
Il doit rester lisible, type et centre sur la presentation.

## Project Rule

Le projet privilegie une composition editoriale et lisible :

- page = orchestration de route
- layout = cadre structurel
- screen = unite d intention
- component = implementation d affichage

## Full screen et scroll

Le modele repose sur un ecran plein viewport par screen. La responsabilite du plein ecran
est repartie entre les trois couches, et la page en reste le garant : c'est elle qui decide
quels screens composent la route et garantit le modele « un ecran par section ».

- **Layout** : definit le plein ecran de base (`h-dvh w-screen overflow-hidden`).
- **Page** : reste neutre au niveau racine (`h-full w-full`, sans `overflow-*` ni `min-h-*`)
  et compose les screens de la route.
- **Screen** : chaque section qui represente un screen redefinit `h-dvh w-screen` pour
  garantir un ecran par section.
- **Scroll interne** : explicite par screen — `min-h-0` sur le parent flex/grid et
  `min-h-0 overflow-y-auto` sur la zone scrollable. Les `min-h-*` ne servent qu'a gerer un
  scroll interne ou une hauteur minimale voulue.
